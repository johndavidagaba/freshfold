## The reuse defect (documented, not quietly fixed, as the brief asks)
lib/verification.ts sets usedAt when a code succeeds, but never CHECKS usedAt. A used code keeps working until it expires.
The agent said so itself: "usedAt is not checked as an invalidating condition because the rules did not request it."
I wrote the rules and I did not say "reject used codes", so the gap is mine as much as the agent's.
Impact here is small (the account is already verified), but the same pattern on a password-reset or login code would let
anyone who sees an old code reuse it for 10 minutes.
