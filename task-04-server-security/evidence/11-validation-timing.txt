## My number and what causes it
The validation library itself costs 0-8 ms (the 8 ms was the first call). It is NOT the cause.
The ~0.9 s warm signup is almost all network:
- breach check:   ~206-308 ms warm: an HTTPS request from Lagos to the Have I Been Pwned API
- database:       ~300 ms: checking the email exists + inserting the user, round trips to Neon in London (eu-west-2)
- rate limiter:   ~280 ms: more round trips to the same London database, to read and update the counter
- Argon2id hash:  ~80 ms in the dev server (21.57 ms in the standalone script; the dev server shares the CPU with compiling)
So the delay comes from three trips out of the country per signup, not from checking the request's shape.
Fixes I would consider: a database region nearer Lagos, keeping rate-limit counters in memory or a fast store,
running the breach check in parallel with the email lookup. I have not made these changes.
